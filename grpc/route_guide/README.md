# gRPC Basics: C++ sample code

The files in this folder are the samples used in [gRPC Basics: C++][],
a detailed tutorial for using gRPC in C++.

[gRPC Basics: C++]:https://grpc.io/docs/languages/cpp/basics

## Configuration

The RouteGuide proto definition is available [here](route_guide.proto).
The server takes the following command-line argument -
* db_path - Path to json file containing database. Defaults to `examples/cpp/route_guide/route_guide_db.json` on bazel builds, and `route_guide_db.json` for non-bazel builds.

## Running the example


Install protobuf & grpc

```
$ make
```
To run the server -

```
$ ./route_guide_server
```

To run the client -

```
$ ./route_guide_client
```

## Pact contract tests

The consumer test configures a V4 synchronous message interaction with
`pact-protobuf-plugin` 0.8.0, starts the plugin's gRPC mock transport, and calls
the production `RouteGuideClient`. It writes the pact consumed by the provider
test, which starts `RouteGuideServer` on an ephemeral port and verifies the
contract against that real service.

On macOS, install the build dependencies and download the Pact FFI library and
protobuf plugin for the current architecture:

```bash
brew install abseil boost cmake grpc protobuf

case "$(uname -m)" in
	arm64) PACT_ARCH=aarch64 ;;
	x86_64) PACT_ARCH=x86_64 ;;
	*) echo "Unsupported architecture: $(uname -m)"; exit 1 ;;
esac

export PACT_FFI_ROOT="$HOME/.pact/ffi-v0.5.6"
mkdir -p "$PACT_FFI_ROOT/include" "$PACT_FFI_ROOT/lib"
curl -fsSL \
	https://github.com/pact-foundation/pact-reference/releases/download/libpact_ffi-v0.5.6/pact.h \
	-o "$PACT_FFI_ROOT/include/pact.h"
curl -fsSL \
	"https://github.com/pact-foundation/pact-reference/releases/download/libpact_ffi-v0.5.6/libpact_ffi-macos-${PACT_ARCH}.a.gz" \
	| gzip -dc > "$PACT_FFI_ROOT/lib/libpact_ffi-macos-${PACT_ARCH}.a"
curl -fsSL \
	"https://github.com/pact-foundation/pact-reference/releases/download/libpact_ffi-v0.5.6/libpact_ffi-macos-${PACT_ARCH}.dylib.gz" \
	| gzip -dc > "$PACT_FFI_ROOT/lib/libpact_ffi-macos-${PACT_ARCH}.dylib"

export PACT_PLUGIN_DIR="$HOME/.pact/plugins"
PLUGIN_DIR="$PACT_PLUGIN_DIR/protobuf-0.8.0"
mkdir -p "$PLUGIN_DIR"
curl -fsSL \
	https://github.com/pact-foundation/pact-protobuf-plugin/releases/download/v-0.8.0/pact-plugin.json \
	-o "$PLUGIN_DIR/pact-plugin.json"
curl -fsSL \
	"https://github.com/pact-foundation/pact-protobuf-plugin/releases/download/v-0.8.0/pact-protobuf-plugin-macos-${PACT_ARCH}.gz" \
	| gzip -dc > "$PLUGIN_DIR/pact-protobuf-plugin"
chmod +x "$PLUGIN_DIR/pact-protobuf-plugin"
```

From the repository root, configure, build, and run the tests in the same shell
so `PACT_FFI_ROOT` and `PACT_PLUGIN_DIR` remain set:

```bash
rm -rf build/route-guide

cmake -S grpc/route_guide -B build/route-guide \
	-DRouteGuideBuildPactTests=ON \
	-DPACT_FFI_ROOT="$PACT_FFI_ROOT" \
	-DBoost_ROOT="$(brew --prefix boost)/include"
cmake --build build/route-guide
ctest --test-dir build/route-guide --output-on-failure --verbose
```

CTest runs `route_guide_consumer` before `route_guide_provider`, ensuring the
provider test reads the pact generated by the consumer test.
